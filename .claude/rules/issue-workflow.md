# Issue 駆動ワークフロー

コード変更は GitHub Issue を単位に進める。全作業に共通する完了条件は `definition-of-done.md`、Issue ごとの完了条件は Issue 本文の `## DoD` 節に置く。本ファイルは、複数の agent・人が同じリポジトリで並行して作業するときの着手・判断待ち・手放し方を決める。

1. **衝突を避ける**: `status/in-progress` ラベルが付いた Issue には触らない。着手するときに `status/in-progress` を付ける（ラベルが無ければ `gh label create status/in-progress` で作る）
2. **DoD を書く**: Issue 本文の `## DoD` 節を読み、不足を足す。各項目はチェックボックスにし、検証できる条件にする（試験名・コマンドと期待結果・更新する docs）。範囲外にすることも書く
3. **判断が要る点は先に聞く**: 方針・外部データの取得元や利用条件・費用・ユーザーの作業が要る項目は、DoD の該当項目に「要判断: <何を決めてほしいか・選択肢>」と書いてユーザーに確認し、決まるまでその部分は実装しない。それ以外は承認を待たずに進めてよい
4. **進捗**: 満たした項目を Issue 本文で `[x]` にする。項目を足したら本文に追記する
5. **PR**: 本文で `Closes #N` と紐付け、検証欄に DoD の各項目の結果を書く
6. **終える**: merge したら、または手放すときは `status/in-progress` を外す。手放すときは、どこまで済んだかと残りを Issue にコメントする

`gh` の手順は `git-workflow` skill の issue モード。

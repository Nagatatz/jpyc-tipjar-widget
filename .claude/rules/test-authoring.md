# テスト作成規約

コードを変更するときは、対応するユニットテストを作成・更新する。

- **新機能追加時:** 新しいクラス・メソッドに対するテストを作成する
- **バグ修正時:** 修正内容を検証するリグレッションテストを作成する
- **リファクタリング時:** 既存テストが通ることを確認し、必要に応じてテストも更新する
- **テスト配置:** テストディレクトリ（`src/test/`, `tests/`, `__tests__/` 等）にソースと対応する構成で配置する
- **テスト命名:** テスト対象が明確に分かる命名にする（例: `<対象クラス名>Test`, `<対象モジュール名>.test`）
- **DoD への記載:** Issue の DoD には、実装とセットでテストの作成を含める
- **進め方:** テストを 1 つ書いて失敗を確かめ、通す実装を書いてから次のテストに進む（垂直スライス）。先に全テストを書き切ると、実装で分かった設計の変化にテストが追従できない

**例外:** UI コンポーネント（GUI ベースの設定画面等）や、外部サービスとの結合が必須で単体テストが困難なクラスは、テスト作成を省略してよい。ただし、その場合は Issue にテスト省略の理由を明記すること。

> 検証可能ゴールへの変換は `testing.md`、コミット前の検証項目は `definition-of-done.md` Phase 3 を参照。

# 開発プロセスガイドライン

プロジェクト固有のプロセスが `docs/development-guidelines.md` にある場合はそちらを優先する。
このファイルは汎用的な参考資料として使用する。

## 1. 開発フロー概要

```
要件定義 → 影響分析 → 設計 → 実装 → テスト → レビュー → マージ
    │           │        │       │        │        │
    ▼           ▼        ▼       ▼        ▼        ▼
 Issue      docs/確認  Issue の   コード   品質チェック docs/更新
 (DoD)                方針
```

## 2. 作業開始前の準備

### 2.1 影響分析

新機能の追加や既存機能の修正を行う前に、以下を確認する:

1. **関連ドキュメントの確認**
   - `docs/architecture.md` でアーキテクチャ構成を確認
   - `docs/functional-design.md` で既存の画面仕様・API仕様を確認
   - `docs/glossary.md` で用語の定義を確認

2. **影響範囲の特定**
   - 変更対象のモジュール
   - 依存しているモジュール（上流・下流）
   - 影響を受けるテスト

### 2.2 Issue と DoD の作成

作業ごとに Issue を 1 つ用意し、本文に背景・方針・DoD を書く（フォーマットは `git-workflow` skill の issue モード、完了条件の扱いは `definition-of-done.md`）。

```markdown
## 背景
[なぜこの作業が必要か]

## 方針
[採るアプローチ。選択肢があれば各々の利点・欠点と、採用した理由]

## DoD
- [ ] [確かめられる完了条件]（検証: `<コマンド>`）
- [ ] テスト: [追加・更新するテスト]
- [ ] ドキュメント: [更新するファイル]

## 対象外
- ...
```

## 3. 実装プロセス

### 3.1 実装の順序

プロジェクトのアーキテクチャに応じた順序で実装する。一般的な指針:

1. **型定義・モデル（Domain層）**
2. **ビジネスロジック（Core層）**
3. **データアクセス（Infrastructure層）**
4. **API / プレゼンテーション（Presentation層）**
5. **テスト**

### 3.2 コミット粒度

- 1つの論理的な変更 = 1コミット
- AGENTS.md にコミット規約がある場合はそれに従う
- コミットメッセージは変更の「なぜ」を伝える

### 3.3 品質チェック

各実装ステップ完了後に、プロジェクトのビルドコマンドとテストコマンドを実行する。

**品質基準:**
- ビルドがエラーなしで完了
- テストが全件パス
- 新規コードにコメント規約に沿ったコメントが付与されている

## 4. ドキュメント管理

### 4.1 Single Source of Truth

- 同じ情報を複数箇所に書かない
- 参照リンクで繋ぐ
- AGENTS.md に詳細が記載されている場合は、そちらを参照する

### 4.2 docs/ の更新タイミング

| イベント | 更新対象 |
|---------|---------|
| 新機能追加 | `functional-design.md`, `architecture.md` |
| API変更 | `functional-design.md` |
| アーキテクチャ変更 | `architecture.md` |
| 新しい用語の追加 | `glossary.md` |
| ディレクトリ構成変更 | `repository-structure.md` |
| 開発プロセス変更 | `development-guidelines.md` |

### 4.3 Issue の DoD の管理

- 作業開始時に DoD を書き、承認を得てから着手する
- 進捗は DoD の `[x]` で記録する。途中経過や判断は Issue のコメントに残す
- PR 本文の `Closes #<番号>` で、マージ時に Issue を閉じる

## 5. レビュー観点

### コードレビューチェックリスト

- [ ] プロジェクトのコーディング規約に準拠しているか
- [ ] 命名規則が統一されているか
- [ ] エラーハンドリングが適切か
- [ ] テストが追加されているか
- [ ] コメント規約に従っているか
- [ ] ドキュメントが更新されているか
- [ ] セキュリティ上の問題がないか

## 6. トラブルシューティング

### ビルドエラー

1. エラーメッセージを確認する
2. 依存関係が正しくインストールされているか確認する
3. ビルドキャッシュをクリアして再ビルドする

### テスト失敗

1. エラーメッセージを確認
2. 関連するソースコードを読む
3. 個別テストを実行して原因を特定する
4. デバッグ出力を追加して原因特定

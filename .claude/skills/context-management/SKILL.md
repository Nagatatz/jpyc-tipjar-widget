# コンテキスト管理

## /compact するとき

探索が終わり実装に移る前 / マイルストーン完了後 / 重いデバッグの後 / 方針転換時。残すものを指示する:

```text
/compact 変更したファイル一覧とテストコマンドを保持
```

一部だけ要約するときは `Esc+Esc`（`/rewind`）で起点を選び「Summarize from here」。それより前はそのまま残る。

## コマンドの使い分け

- `/btw <質問>`: 本タスクに無関係な寄り道の質問。回答はオーバーレイに出て履歴に残らない。
- `/rewind`（`Esc+Esc`）: 会話・コード・両方を直前のチェックポイントへ戻す。リスクのある案はまず試し、駄目なら戻す。チェックポイントは Claude の編集だけを追跡し、手動編集や git 操作は戻らないので git の代わりにはしない。
- `/fork`: 調査と実装を別セッションに分ける。調査結果はステアリングドキュメントに書き、実装セッションはそれを読んで始める。

## 避けるセッションの型

- **キッチンシンク**: 無関係なタスクを 1 セッションに詰めない。タスクごとに分ける。
- **繰り返し修正ループ**: 同じ修正が 3 回失敗したら、アプローチを根本から見直す。
- **無限探索**: 探索前に「何を知りたいか」を決め、分かったら止める。

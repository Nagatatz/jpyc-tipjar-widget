# Deep Research

`$ARGUMENTS` を調べる（例: `/deep-research how mocks are bound`）。

1. **発見**: Glob で構造を掴み、Grep で同義語・関連語も検索し、候補をコア / 周辺 / テストに分ける。
2. **読む**: コア実装で設計意図、周辺で利用パターン、テストで期待挙動を掴む。
3. **依存を追う**: 上流（依存する基盤）と下流（利用箇所）。
4. **抽出**: プロジェクト固有の規約、エッジケース処理の有無、TODO / FIXME / 技術的負債。

メイン会話には要約だけ返す（詳細はサブエージェント側に留める）:

```markdown
## 全体像            ← 1〜2 段落
## 主要コンポーネント  ← `path`: 役割（1 行）
## パターン / 規約
## 注意点            ← バグの匂い / TODO / 負債（ファイル:行）
```
